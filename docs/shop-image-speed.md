# 상점 상품 이미지 속도 개선 작업 기록

- 브랜치: `feat/shop-image-speed` (main `990625d`, 아바타 속도 PR #19까지 반영된 지점에서 시작)
- 목표: 상점 아래 상품 칸의 이미지가 늦게 뜨는 것을 줄인다.
- 진행 방식: 단계마다 구현 → 측정·테스트 → 이 문서에 기록 → 보고 후 커밋.

## 처음 상태 측정 (2026-11-26, 에뮬레이터 Pixel 8, 검증 계정)

상품 이미지는 `RemoteImage`(직접 만든 이미지 표시, 인증 사진과 함께 씀)로 받는다. 측정용 기록을 잠깐 넣어 이미지마다 받는 시간을 쟀다(되돌림).

| 동작 | 새로 받은 이미지 | 한 장 받는 시간 | 누른 뒤 마지막 이미지까지 |
| --- | --- | --- | --- |
| 앱을 켜고 처음 상점(아바타) | 6장 | 1.6초 | 약 2.9초 |
| 가구 탭 | 12장 | 3.1~3.8초 | 약 4.2초 |
| 아바타 탭에서 아래로 스크롤 | 12장 | 1.4~2.0초 | 약 2.5초 |
| 다시 아바타 탭 / 홈 갔다가 다시 상점 | 0장(메모리) | 바로 | 바로 |

- 서버 이미지: 상품 108개(아바타 57, 가구 51) 모두 512×512 PNG, 35~193KB. S3가 `Cache-Control: public, max-age=31536000, immutable`(1년 저장 허용)로 보낸다. PC에서 받으면 한 장 0.1~0.2초.
- "누른 뒤" 시간은 탭을 찾는 측정 도구 시간(약 3.8초)을 뺀 값이다.

원인:
1. **기기에 저장하지 않는다.** 메모리에만 두어서 앱을 다시 켜면 모두 다시 받는다. 서버의 1년 저장 허용을 쓰지 않았다.
2. **필요보다 큰 그림으로 들고 있다.** 카드 칸(72dp, 약 189픽셀)에 512×512 원본 그대로 디코딩해 한 장 1MB. 메모리 보관 한도 24MB에 24장만 들어가 탭을 오가거나 스크롤하면 앞의 것이 밀려나 다시 받는다.
3. **보일 때에야 받기 시작한다.** 한꺼번에 12장을 받으면 연결을 새로 많이 열어 한 장에 3초 넘게 걸린다.

- 받는 크기 자체(512 → 256)를 줄이는 것은 앱만으로는 안 된다. S3에는 512 파일 하나뿐이고 크기를 바꿔 주는 기능이 없다. 필요하면 백엔드가 256 썸네일을 따로 올려야 한다(1~3단계 뒤에도 첫 받기가 느리면 요청).

## 단계 계획

| # | 작업 | 예상 효과 | 상태 |
| --- | --- | --- | --- |
| 1 | 받은 이미지를 기기에 저장(서버가 허용한 것만, 50MB) | 앱을 다시 켜도 한 번 본 이미지는 바로 | 완료 |
| 2 | 칸 크기에 맞게 줄여서 메모리에 보관 | 메모리에 약 4배 더 들어가 탭을 오가도 다시 읽지 않음 | 보류(1단계 뒤 효과 작음, 아래) |
| 3 | 홈에서 쉴 때 모든 상품 이미지를 기기에 미리 받기(사용자 선택: 상점을 열 때가 아니라 홈에서) | 처음 보는 탭·스크롤도 이미 받아 둠 | 완료 |

- 2단계 보류 이유: 1단계 뒤에는 메모리에서 밀려난 이미지를 인터넷이 아니라 기기에서 다시 읽어(한 장 0.03~0.18초) 남는 차이가 "바로 뜸"과 "잠깐 빈칸" 정도다. 더 큰 문제인 처음 받기(3단계)를 먼저 했다.

## 1단계. 기기에 저장

### 무엇을 바꿨나

| 파일 | 내용 |
| --- | --- |
| `ui/proof/RemoteImage.kt` | 이미지 연결에 OkHttp HTTP 캐시(`cache/remote_images`, 50MB)를 붙였다(`RemoteImages`, `imageClient`). 받기를 `fetchToFile`로 나눠 테스트할 수 있게 했다 |

- **서버가 저장해도 된다고 한 것만** 저장한다(HTTP 캐시 규칙). 상점·가구 썸네일은 1년 저장 허용이라 다음부터 인터넷 없이 기기에서 읽는다.
- 저장 금지·유효기간이 없는 응답(인증 사진 등)은 전과 같이 매번 받는다. 실패한 응답은 저장하지 않는다.
- 저장 폴더는 앱 캐시 폴더 안이라 저장 공간이 부족하면 시스템이 지울 수 있다(지워지면 다시 받음). 50MB를 넘으면 오래 안 쓴 것부터 지운다.
- 새 라이브러리는 추가하지 않았다(이미 쓰는 OkHttp의 기능).

### 측정 (에뮬레이터, 측정용 기록은 되돌림)

| 동작 | 전 (매번) | 1단계 후: 처음 받을 때 | **1단계 후: 앱을 껐다 켰을 때** |
| --- | --- | --- | --- |
| 처음 상점(아바타 6장) | 한 장 1.6초 | 1.1초 | **0.6초**(첫 저장소 열기 포함) |
| 가구 탭(12장) | 한 장 3.1~3.8초 | 3.3~4.0초 | **0.06~0.18초** |
| 아래로 스크롤(12장) | 한 장 1.4~2.0초 | 1.4~1.9초 | **0.03~0.09초** |

이미지만의 시간(첫 이미지 시작 → 마지막 이미지 끝), 앱을 껐다 켰을 때: 처음 상점 0.59초, 가구 탭 0.13초, 스크롤 0.43초. 누른 뒤 이미지 받기 시작까지는 약 0.1~0.2초.

- 처음 받을 때(설치 직후·새 상품)는 전과 같다 → 3단계(미리 받기) 대상.
- 저장 폴더: 상품 이미지 일부(약 30장)를 본 뒤 3.4MB. 108장 모두는 약 15MB(3단계에서 잼).

## 3단계. 홈에서 쉴 때 상품 이미지 미리 받기

### 무엇을 바꿨나

| 파일 | 내용 |
| --- | --- |
| `ui/shop/ShopImagePrefetch.kt` (새 파일) | `ShopImagePrefetcher`: 상품 목록(아바타 → 가구, 한 번에 100개씩)에서 카드 이미지 주소를 모아 **동시에 4장씩** 기기 저장소에 받는다. 앱이 켜진 동안 한 번. `ShopImagePrefetch`: 로그인 뒤 1.5초 + 화면 스레드가 쉴 때 시작(아바타 미리 준비와 같은 시점) |
| `ui/proof/RemoteImage.kt` | `RemoteImages.prefetch`·`fetchToCache`: 화면에 그리지 않고 저장소에만 받기(끝까지 읽어야 저장됨) |
| `ui/avatar/AvatarPrewarm.kt` | 화면 스레드가 쉴 때까지 기다리는 함수(`awaitMainThreadIdle`)를 함께 쓰도록 `internal`로 |
| `data/auth/AppContainer.kt` | `prefetchShopImages` 스위치(기본 켬) |
| `MainActivity.kt` | 스위치가 켜져 있으면 `ShopImagePrefetch` |
| `androidTest/.../TestDQApplication.kt` | UI 테스트는 인터넷 없이 돌도록 끔 |

- **메모리에 올리지 않고 파일로만** 받는다. 디코딩도 하지 않아 화면 스레드 일이 늘지 않는다.
- 이미 저장된 이미지는 인터넷을 쓰지 않는다(1단계 저장소). 실제로 받는 것은 처음 한 번과 새 상품뿐이다.
- 로그아웃 상태에서는 하지 않는다. 목록을 못 받으면(인터넷 끊김) 끝난 것으로 치지 않아 다음 로그인·앱 재시작 때 다시 한다. 이미지 하나가 실패해도 나머지는 계속하고, 실패한 것은 화면에 보일 때 평소처럼 받는다.
- 미리 받는 중에 상점을 열어도 화면의 칸은 평소처럼 받는다(같은 이미지를 두 번 받을 수는 있음).
- **처음 한 번 받는 양: 108장, 약 15MB**(한 장 평균 140KB). 백엔드가 256 크기 썸네일을 주면 약 4분의 1로 줄어든다.

### 측정 (에뮬레이터, 측정용 기록은 되돌림)

저장소를 비우고 로그인 → 홈:
- 미리 받기: 로그인 약 8초 뒤 시작해 약 10초 만에 108장 모두 저장(로그인부터 약 18초).
- 로그아웃 상태에서는 100초 동안 아무것도 받지 않음(확인).

저장소를 비우고 앱을 켬 → 홈에서 25초 → 처음 상점 (한 장 받는 시간):

| 동작 | 전 (처음) | 1단계 후 (처음) | **3단계 후 (처음)** |
| --- | --- | --- | --- |
| 처음 상점(아바타 6장) | 1.6초 | 1.1초 | **0.18~0.6초** |
| 가구 탭(12장) | 3.1~3.8초 | 3.3~4.0초 | **0.05~0.1초** |
| 아래로 스크롤(12장) | 1.4~2.0초 | 1.4~1.9초 | **0.02~0.09초** |

이미지만의 시간(첫 시작 → 마지막 끝): 처음 상점 0.61초, 가구 탭 0.10초, 스크롤 0.35초.
