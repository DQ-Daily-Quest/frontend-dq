# 아바타 3D 불러오기 속도 개선 작업 기록

- 브랜치: `feat/avatar-speed` (main `6065741`, PR #18까지 반영된 지점에서 시작)
- 목표: 상점 등 3D 아바타 화면을 **열 때마다** 1~2초씩 걸리던 것을 줄인다.
- 진행 방식: 단계마다 구현 → 측정·테스트 → 이 문서에 기록 → 보고 후 커밋. 효과와 위험을 보고 어디까지 넣을지 정한다.

## 처음 상태 측정 (2026-11-25, 에뮬레이터 Pixel 8, 검증 계정)

상점 탭을 4번 열며 단계별 시간을 쟀다(측정용 기록은 잠깐 넣었다가 되돌림).

| 회차 | 탭 → 아바타 다 뜸 | 서버에서 착용 정보 받기 | 3D 엔진 준비 | 파츠 6개 모델 만들기 |
| --- | --- | --- | --- | --- |
| 1 (3D 파일 처음 받음) | 4.3초 | 0.54초 | 0.19초 | 받기 약 2.7초 + 0.55초 |
| 2 | 1.7초 | 0.37초 | 0.25초 | 0.70초 |
| 3 | 1.2초 | 0.22초 | 0.18초 | 0.54초 |
| 4 | 1.4초 | 0.24초 | 0.18초 | 0.52초 |

- 3D 파일(GLB)은 이미 기기에 저장(캐시, 100MB)하고 있어 2번째부터는 받지 않는다. **매번 느린 원인은 파일 받기가 아니다.**
- 매번 걸리는 것:
  1. 상점을 열 때마다 서버에서 내 착용 정보(내 정보 + 보유 아이템)를 받고, **받을 때까지 3D를 시작하지 않음**
  2. 3D 엔진을 화면마다 새로 만들고 닫을 때 버림 + 로딩 표시를 먼저 그리려는 2프레임 대기
  3. 파츠 모델을 하나씩 만들고, 모두 만든 뒤에 한꺼번에 보여줌
- "모든 파츠를 GLB 하나로 앱에 넣기"는 매번 느린 원인과 관계없어 하지 않는다(44MB를 매번 통째로 모델로 만들어 오히려 느려짐).

## 1단계. 마지막 착용 정보로 바로 시작

### 무엇을 바꿨나

| 파일 | 내용 |
| --- | --- |
| `data/avatar/MyAvatarRepository.kt` | 불러오기·착용·캐릭터 만들기 결과를 **계정별로 기억**(`cached(userId)`). 앱이 켜져 있는 동안만, 다른 계정에는 주지 않는다 |

## 2단계. 3D 엔진을 앱 전체에서 하나만

### 무엇을 바꿨나

| 파일 | 내용 |
| --- | --- |
| `ui/avatar/AvatarEngine.kt` (새 파일) | 앱 전체가 함께 쓰는 **엔진·모델 로더·재질 로더·환경 조명**. 처음 3D 화면을 열 때 한 번 만들고 지우지 않는다 |
| `ui/avatar/AvatarView.kt` | SceneView에 공유 자원을 넘긴다. 화면마다 필요한 것(View·Renderer·Scene·조명·카메라)은 그대로 화면마다. 각 화면이 **자기가 만든 모델 목록(`SceneModels`)**을 관리하고 떠날 때 지운다 |

SceneView 기본값은 3D 화면마다 엔진, 모델 로더(재질 셰이더 포함), 재질 로더, 환경 조명(`neutral_ibl.ktx` 파일을 읽어 그래픽 메모리에 올림)을 새로 만들고 화면을 떠나면 모두 버렸다. 이제 처음 한 번만 만든다. 상점, 캐릭터 만들기, 얼굴 공장이 같은 엔진을 쓴다.

### 모델 지우기 (가장 조심한 부분)

전에는 화면을 떠나면 그 화면의 모델 로더가 사라지며 모델을 모두 지웠다. 로더를 함께 쓰면 그 일이 없어지므로, 각 화면이 직접 지운다.
- 다 만든 모델을 화면의 목록에 등록하고, 바꿔 입어 빠진 모델은 2프레임 뒤에(그리는 중이 아닐 때) 지운다(전과 같음).
- 화면을 떠나면 목록의 모델을 모두 지운다. 목록에 있는 것만 한 번씩 지워 **두 번 지우기(강제 종료)**를 막는다.
- **텍스처를 만드는 중에 화면이 사라지면, 텍스처가 다 만들어진 뒤에 지운다.** 로더를 함께 쓰므로 진행 중인 작업을 통째로 취소할 수 없고(다른 화면 것까지 취소됨), 만드는 중인 모델을 지우면 로더가 지워진 모델의 텍스처를 계속 만들다 강제 종료될 수 있기 때문이다.

## 3단계. 파츠 모델 보관·재사용

### 알아낸 것 (설계를 바꾼 이유)

- 처음 계획은 "보관한 모델의 복사본(인스턴스)을 만들어 쓰기"였다. 그런데 Filament에는 **복사본 하나만 지우는 기능이 없고**(원본을 지울 때 함께 지워짐), 화면마다 복사본을 만들면 계속 쌓인다.
- 더 큰 문제: SceneView의 모델 노드(`ModelNode`)는 화면을 떠날 때 **모델의 엔티티(그려지는 부품)까지 지운다**(`Node.destroy` → `safeDestroyEntity`, `safeDestroyRenderable`). 그래서 모델 노드로 그리는 한 보관한 모델을 다시 쓸 수 없다.
- 그래서 **모델 노드를 쓰지 않고, 보관한 모델의 엔티티를 SceneView 장면에 직접 넣고 뺀다**(지우지 않음). 장면을 지워도 엔티티는 지워지지 않는다. 상점과 얼굴 공장이 같은 옷이면 같은 모델을 두 장면에 함께 넣는다(Filament는 한 엔티티를 여러 장면에 넣을 수 있다). 복사본은 만들지 않는다.
- 모델 노드가 매 프레임 하던 일(애니메이션, 뼈대 계산, 빈 경계 상자 처리)을 확인했다. 실제 GLB는 **뼈대·애니메이션이 없는 고정 모델**(메시 1개)이라, 장면에 넣을 때 빈 경계 상자 처리만 한 번 하면 된다(`allowEmptyBounds`).
