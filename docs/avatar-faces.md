# 프로필 얼굴을 각자 아바타 얼굴로 작업 기록

- 브랜치: `feat/avatar-faces` (STEP 10이 합쳐진 `main` c67e8db에서 시작)
- 목표: 홈 지도·방 화면·마이페이지 등에 보이는 고정 얼굴 그림을 **각 사람의 실제 3D 아바타 얼굴**로 바꾼다.
- 진행 방식: 단계마다 구현 → 빌드·테스트 → 이 문서에 기록 → 보고 후 커밋

## 시작 전 상태 (2026-11-24 확인)

- 얼굴 자리는 모두 앱에 들어 있는 고정 그림(남자아이·여자아이 2장, 사람 아이콘)이다. 방 화면 멤버 목록에는 "멤버 아바타는 임시 이미지예요."라고 적혀 있다.
- 서버의 `avatarUrl`은 항상 null이다. 백엔드 코드 주석: "아바타 이미지 합성은 클라이언트 담당이라 서버는 null 고정". → **얼굴 사진은 앱이 직접 만든다.**
- 서버가 이미 주는 아바타 정보(착용 아이템 ID):
  - 방 멤버 목록 `GET /rooms/{id}/members`의 `avatar`
  - 인증·피드 작성자(`ProofUser`)의 `avatar` (앱 DTO는 아직 안 읽음)
  - 다른 사람 프로필 `GET /users/{id}`, 내 정보 `GET /users/me`
  - 착용 아이템 ID → 3D 파일 주소: `GET /shop/items/batch?ids=`
- 서버가 주지 않는 것: 방 목록(`/rooms/mine`)에는 멤버가 없다. 짧은 사용자 정보(`UserBrief`: 방장, 마지막 꾸민 사람 등)에는 아바타가 없다. → 앱이 추가로 조회한다. 백엔드 요청은 필요할 때만(아래 "백엔드").

## 방식

얼굴마다 3D 화면을 띄우면 무겁다(STEP 9: 화면마다 3D 엔진 하나). 그래서
1. 앱 안에 **보이지 않는 3D 화면 하나**를 두고, 아바타를 얼굴만 가깝게 비춰 **한 번 찍어 PNG로 저장**한다.
2. 저장 이름은 **착용 조합**(성별 + 착용 파츠)으로 정한다. 같은 조합은 다시 찍지 않고, 옷을 바꾸면 조합이 달라져 새로 찍는다(예전 얼굴이 남지 않음).
3. 화면에는 그 사진을 동그랗게 보여준다. 처음 찍는 동안은 지금의 고정 그림(성별별)을 보여준다.

다른 사람이 아바타를 바꾸면, 내 앱은 그 화면이 서버에서 정보를 다시 받을 때(방에 들어오거나 홈으로 돌아올 때) 새 얼굴을 보여준다. 내가 바꾸면 바로 바뀐다.

### 찍는 방법

SceneView는 3D 화면을 안에서 `TextureView`로 만드는데 밖으로 내주지 않는다(`Scene.kt`의 `AndroidView { TextureView(ctx) }`). 그래서 **화면 뷰 트리에서 `AvatarView` 자리와 겹치는 TextureView를 찾아 `getBitmap()`** 으로 읽는다. `AvatarView`가 `isOpaque = false`라 **배경은 투명**하게 나온다(동그랗게 잘라 쓰기 좋다).

### 얼굴 카메라 값

처음 값(높이 1.05m, 거리 0.95m)은 너무 가까워 머리 위·양옆이 잘렸다. 화면에서 바꿔 가며 **높이 1.11m, 거리 1.3m, 바라보는 점 높이 1.08m**로 정했다. 남·여 머리 전체와 큰 노란 레인 모자까지 정사각형 안에 들어온다. `AvatarCamera.FACE`에 고정했다.

### 실험 중 만난 문제 2개

**① 이전 의상이 찍힘.** "준비됨 + 3D 화면이 3번 그린 뒤"에 찍었더니, 의상을 바꾼 직후 새 모습이 올라오기 전(이전 의상이나 모자가 빠진 중간 모습)이 찍힌 경우가 있었다. 테스트에서는 빈 사진이 찍히기도 했다.
→ `captureSettled`: 0.15초마다 찍어서 **비어 있지 않고(불투명한 점 2% 이상) 바로 전 사진과 거의 같을 때만** 받는다. 화면이 다 올라와 멈춘 모습만 저장된다.

**② "거의 같음"이 늘 실패.** 두 사진을 비교하니 같은 장면인데도 87%만 같았다. 투명한 배경의 점은 투명도가 0이어도 색 값이 프레임마다 달라졌기 때문이다(로그로 확인).
→ 색에 투명도를 곱해서 비교(둘 다 투명하면 같음). 같은 장면은 100% 같다고 나온다. 기준: 격자 32×32 점 중 98% 이상이 색 차이 12 이하.

### 테스트가 확인하는 것 (`AvatarFaceTestScreenTest`, 실제 S3, 인터넷 필요)

"모두 찍기"로 4장을 찍고:
- 4장 모두 저장, 배경이 투명(불투명 80% 미만), 아바타가 보임(15% 초과), 가운데(얼굴)가 비어 있지 않음.
- **바뀐 의상이 찍혔는지**: 노란 레인 모자를 쓴 "여 섞어 입기"만 노란 점이 많다(실측 2.69%). 모자가 없는 "남 기본"·"여 기본"은 거의 없다(0%, 0.02%). 기준은 그 사이(모자 1.5% 초과, 모자 없음 0.5% 미만). 처음 구현처럼 이전 의상이 찍히면 실패한다.

처음 기준(3%)은 실측 전에 정해서 실패했다. 사진 4장을 직접 열어 맞게 찍힌 것을 확인한 뒤 실측값으로 고쳤다.

3D 화면이 매 프레임 그려서 테스트는 STEP 9 3D 테스트와 같이 프레임 시계를 직접 넘기고, 클릭은 클릭 동작을 직접 실행한다.

### 2단계로 넘길 것

- 찍을 때는 반드시 `captureSettled`를 쓴다(빈 사진·이전 모습 방지).
- 찍는 3D 화면은 실제 화면에 붙어 있어야 그려진다(TextureView). 2단계에서는 앱 화면 맨 아래(다른 화면에 가려지는 자리)에 작게 하나 두는 방식을 시험한다.
- 3D 엔진을 처음 만드는 시간이 길다(에뮬레이터 수십 초, STEP 9에서는 5~6초 멈춤). 얼굴 공장은 한 번 만들어 계속 쓰고, 화면에는 그동안 기본 그림을 보여준다.
