# 프로필 얼굴을 각자 아바타 얼굴로 작업 기록

- 브랜치: `feat/avatar-faces` (STEP 10이 합쳐진 `main` c67e8db에서 시작)
- 목표: 홈 지도·방 화면·마이페이지 등에 보이는 고정 얼굴 그림을 **각 사람의 실제 3D 아바타 얼굴**로 바꾼다.
- 진행 방식: 단계마다 구현 → 빌드·테스트 → 이 문서에 기록 → 보고 후 커밋

## 시작 전 상태 (2026-11-24 확인)

- 얼굴 자리는 모두 앱에 들어 있는 고정 그림(남자아이·여자아이 2장, 사람 아이콘)이다. 방 화면 멤버 목록에는 "멤버 아바타는 임시 이미지예요."라고 적혀 있다.
- 서버의 `avatarUrl`은 항상 null이다. 백엔드 코드 주석: "아바타 이미지 합성은 클라이언트 담당이라 서버는 null 고정". → **얼굴 사진은 앱이 직접 만든다.**
- 서버가 이미 주는 아바타 정보(착용 아이템 ID):
  - 방 멤버 목록 `GET /rooms/{id}/members`의 `avatar`
  - 인증·피드 작성자(`ProofUser`)의 `avatar` (앱 DTO는 아직 안 읽음)
  - 다른 사람 프로필 `GET /users/{id}`, 내 정보 `GET /users/me`
  - 착용 아이템 ID → 3D 파일 주소: `GET /shop/items/batch?ids=`
- 서버가 주지 않는 것: 방 목록(`/rooms/mine`)에는 멤버가 없다. 짧은 사용자 정보(`UserBrief`: 방장, 마지막 꾸민 사람 등)에는 아바타가 없다. → 앱이 추가로 조회한다. 백엔드 요청은 필요할 때만(아래 "백엔드").

## 방식

얼굴마다 3D 화면을 띄우면 무겁다(STEP 9: 화면마다 3D 엔진 하나). 그래서
1. 앱 안에 **보이지 않는 3D 화면 하나**를 두고, 아바타를 얼굴만 가깝게 비춰 **한 번 찍어 PNG로 저장**한다.
2. 저장 이름은 **착용 조합**(성별 + 착용 파츠)으로 정한다. 같은 조합은 다시 찍지 않고, 옷을 바꾸면 조합이 달라져 새로 찍는다(예전 얼굴이 남지 않음).
3. 화면에는 그 사진을 동그랗게 보여준다. 처음 찍는 동안은 지금의 고정 그림(성별별)을 보여준다.

다른 사람이 아바타를 바꾸면, 내 앱은 그 화면이 서버에서 정보를 다시 받을 때(방에 들어오거나 홈으로 돌아올 때) 새 얼굴을 보여준다. 내가 바꾸면 바로 바뀐다.

### 찍는 방법

SceneView는 3D 화면을 안에서 `TextureView`로 만드는데 밖으로 내주지 않는다(`Scene.kt`의 `AndroidView { TextureView(ctx) }`). 그래서 **화면 뷰 트리에서 `AvatarView` 자리와 겹치는 TextureView를 찾아 `getBitmap()`** 으로 읽는다. `AvatarView`가 `isOpaque = false`라 **배경은 투명**하게 나온다(동그랗게 잘라 쓰기 좋다).

### 얼굴 카메라 값

처음 값(높이 1.05m, 거리 0.95m)은 너무 가까워 머리 위·양옆이 잘렸다. 화면에서 바꿔 가며 **높이 1.11m, 거리 1.3m, 바라보는 점 높이 1.08m**로 정했다. 남·여 머리 전체와 큰 노란 레인 모자까지 정사각형 안에 들어온다. `AvatarCamera.FACE`에 고정했다.

### 실험 중 만난 문제 2개

**① 이전 의상이 찍힘.** "준비됨 + 3D 화면이 3번 그린 뒤"에 찍었더니, 의상을 바꾼 직후 새 모습이 올라오기 전(이전 의상이나 모자가 빠진 중간 모습)이 찍힌 경우가 있었다. 테스트에서는 빈 사진이 찍히기도 했다.
→ `captureSettled`: 0.15초마다 찍어서 **비어 있지 않고(불투명한 점 2% 이상) 바로 전 사진과 거의 같을 때만** 받는다. 화면이 다 올라와 멈춘 모습만 저장된다.

**② "거의 같음"이 늘 실패.** 두 사진을 비교하니 같은 장면인데도 87%만 같았다. 투명한 배경의 점은 투명도가 0이어도 색 값이 프레임마다 달라졌기 때문이다(로그로 확인).
→ 색에 투명도를 곱해서 비교(둘 다 투명하면 같음). 같은 장면은 100% 같다고 나온다. 기준: 격자 32×32 점 중 98% 이상이 색 차이 12 이하.

### 테스트가 확인하는 것 (`AvatarFaceTestScreenTest`, 실제 S3, 인터넷 필요)

"모두 찍기"로 4장을 찍고:
- 4장 모두 저장, 배경이 투명(불투명 80% 미만), 아바타가 보임(15% 초과), 가운데(얼굴)가 비어 있지 않음.
- **바뀐 의상이 찍혔는지**: 노란 레인 모자를 쓴 "여 섞어 입기"만 노란 점이 많다(실측 2.69%). 모자가 없는 "남 기본"·"여 기본"은 거의 없다(0%, 0.02%). 기준은 그 사이(모자 1.5% 초과, 모자 없음 0.5% 미만). 처음 구현처럼 이전 의상이 찍히면 실패한다.

처음 기준(3%)은 실측 전에 정해서 실패했다. 사진 4장을 직접 열어 맞게 찍힌 것을 확인한 뒤 실측값으로 고쳤다.

3D 화면이 매 프레임 그려서 테스트는 STEP 9 3D 테스트와 같이 프레임 시계를 직접 넘기고, 클릭은 클릭 동작을 직접 실행한다.

### 2단계로 넘길 것

- 찍을 때는 반드시 `captureSettled`를 쓴다(빈 사진·이전 모습 방지).
- 찍는 3D 화면은 실제 화면에 붙어 있어야 그려진다(TextureView). 2단계에서는 앱 화면 맨 아래(다른 화면에 가려지는 자리)에 작게 하나 두는 방식을 시험한다.
- 3D 엔진을 처음 만드는 시간이 길다(에뮬레이터 수십 초, STEP 9에서는 5~6초 멈춤). 얼굴 공장은 한 번 만들어 계속 쓰고, 화면에는 그동안 기본 그림을 보여준다.

```
adb shell am start -n com.dailyquest.app/.debug.AvatarFaceTestActivity
```

## 2단계. 얼굴 사진 공장

### 무엇을 만들었나

| 파일 | 내용 |
| --- | --- |
| `data/avatar/FaceStore.kt` (새 파일) | `FaceKey`: 착용 조합(슬롯별 GLB 주소) → 사진 이름(SHA-256 앞 40자). 순서와 관계없이 같고, 옷·모자가 바뀌면 달라진다. 얼굴 카메라를 바꾸면 `VERSION`을 올려 예전 사진을 버린다. `FaceStore`: 얼굴 PNG 기기 저장(`cacheDir/avatar_faces`, 20MB, 오래 안 쓴 것부터 지움, 임시 파일 → 이름 바꾸기) |
| `ui/avatar/FaceStudio.kt` (새 파일) | 찍을 차례(대기열). 같은 얼굴은 한 번만, 이미 있거나 빈 조합은 건너뜀. 성공하면 저장·`version` 올림, 실패하면 맨 뒤로(다른 얼굴 먼저), 2번 실패하면 이번 실행에서는 포기. `FaceStudios.get(context)`로 앱 전체가 같은 공장을 쓴다 |
| `ui/avatar/FaceStudioHost.kt` (새 파일) | `FaceStudioHost`: 실제로 찍는 3D 화면(128dp). **화면 맨 아래 층에 두고 다른 화면이 덮는다**(TextureView는 화면에 붙어 그려져야 내용이 생겨서 숨기지 않고 가린다). 대기열이 처음 생길 때 만들고 그 뒤로 계속 둔다(3D 엔진을 다시 만들지 않게). 준비 + 10프레임 + 0.3초 뒤 `captureSettled`로 찍어 256×256 PNG로 줄인다. 한 얼굴 30초 넘으면 실패 처리. `rememberAvatarFace(parts, studio)`: 메모리(8MB) → 기기 → 없으면 공장에 부탁, 찍히면 다시 그림. 없으면 null(화면은 기본 그림) |
| `debug/FaceStudioTestActivity.kt` (새 파일) | "DQ 얼굴 공장 테스트" 화면(런처 아이콘 없음). 실제 앱처럼 공장을 맨 아래에 두고 불투명한 화면으로 덮은 뒤, 4가지 의상 얼굴을 64dp·32dp로 보여준다 |

## 3단계. 사람 → 착용 파츠

서버가 주는 다른 사람의 아바타는 슬롯별 **아이템 ID**뿐이다(`avatar: {skin, eyes, hair, top, bottom, shoes, hat}`). 얼굴을 찍으려면 3D 파일 주소가 필요하므로, 아이템 ID를 `GET /shop/items/batch?ids=`로 3D 주소로 바꾼다.

### 무엇을 만들었나

| 파일 | 내용 |
| --- | --- |
| `data/remote/DqApi.kt` | `getShopItemsBatch(ids)` 추가 (`GET /shop/items/batch?ids=1,2,3`, 최대 100개, 없는 ID는 빠짐) |
| `data/avatar/AvatarFaceRepository.kt` (새 파일) | 아바타 → 얼굴 파츠. `faceParts(avatar)`, `faceParts(avatars)`(여러 사람 한 번에), `cachedFaceParts(avatar)`(이미 아는 것만으로 바로). 얼굴 슬롯 `FACE_PARTS`, 주소를 이미 아는 내 아바타용 `faceOnly()` |
| `data/auth/AppContainer.kt` | `avatarFaceRepository` 등록 (한 줄) |
| `androidTest/.../TestDQApplication.kt` | 테스트용 가짜 서버에 batch 응답 추가 |

### 정한 것

- **얼굴에 보이는 슬롯만 쓴다: 피부(몸)·눈·머리·모자·상의.** 얼굴 카메라에는 하의·신발이 안 보인다. 두 슬롯을 빼면 하의·신발만 바꿨을 때 착용 조합 이름이 그대로라 **얼굴을 다시 찍지 않는다.** 상의는 목·어깨가 살짝 보여서 넣었다.
- **모르는 아이템만 묻는다.** 여러 사람의 아이템 ID를 모아 한 번에 묻고, 100개가 넘으면 나눈다. 받은 3D 주소는 앱이 켜져 있는 동안 기억한다(아이템 주소는 바뀌지 않으므로 계정이 바뀌어도 그대로 씀). 기본 아이템은 모두 같은 ID라, 한 방에 친구가 여럿이어도 보통 한 번(아이템 몇 개)이면 된다.
- **서버에 없는 아이템·3D 파일이 없는 아이템**은 그 슬롯만 빼고 그리며, "없음"으로 기억해 다시 묻지 않는다.
- **서버 오류**면 실패를 돌려주고 기억하지 않는다(다음에 다시 묻는다). 화면은 기본 그림을 보여주면 된다(4단계).
- 여러 화면이 동시에 불러도 같은 아이템을 두 번 묻지 않게 한 번에 하나씩 받는다.

### 실서버 확인 (조회만)

검증 계정으로 비공개 방 23의 멤버 목록(`GET /rooms/23/members`) → 얼굴 슬롯 아이템 ID 4개 → `GET /shop/items/batch` → 200, 4개 모두 3D 주소가 나왔다(`boy/DQ_Boy_01_Body_DeepBrown.glb`, `DQ_Boy_02_Eyes.glb`, `DQ_Boy_03_Hair.glb`, `DQ_Boy_04_Top.glb`). 모자는 안 쓴 상태라 null이었다. 서버 명세(api.md 7.1.1)상 ID가 100개를 넘으면 `VALIDATION_ERROR`이므로 앱은 100개씩 나눈다.

### 정한 것

- **내 얼굴은 세션의 내 정보로 그린다.** 착용을 바꾸면(상점·꾸미기) 서버 응답으로 세션이 갱신되므로 **마이페이지 얼굴이 바로 새 조합으로 바뀐다**(새 사진을 찍는 동안은 성별 그림). 다른 화면에서도 내 얼굴은 같은 값을 쓴다.
- **방 멤버 줄에서 나는 세션의 착용을 쓴다.** 서버 멤버 목록은 방에 들어올 때 받은 것이라, 방금 옷을 바꿨다면 예전 착용이 있을 수 있다. 다른 멤버는 방에 다시 들어오면 새 착용으로 바뀐다.
- **멤버 얼굴 정보는 한 번에 받는다.** 멤버 전원의 아이템 ID를 모아 batch 한 번(이미 아는 아이템이면 0번).
- **내 얼굴은 받아 오는 동안에도 성별 그림**을 보여준다(세션이 성별을 안다). 다른 사람은 아이템을 받아야 성별을 알아서 그 사이 사람 아이콘.
- 마이페이지 얼굴 태그를 `myAvatarPlaceholder`에서 `myProfileFace`로 바꿨다. 같은 이름을 상점 3D 미리보기(테스트 환경)도 쓰고 있어서 겹치지 않게 했다.

### 실서버 확인 (에뮬레이터, 검증 계정)

- 앱을 새로 설치하고 검증 계정으로 로그인 → 마이 탭: 처음에는 남자아이 그림 → 10~30초 사이에 실제 아바타 얼굴(어두운 피부·보라 머리, 계정의 실제 착용)로 바뀌었다. 새로 설치해서 3D 파일을 처음 받느라 오래 걸렸다(파일이 있으면 한 장 1~1.4초, 2단계).
- 홈 → "STEP10 검증"(방 23): 멤버 줄에 같은 얼굴이 바로 보였다(저장된 사진). "임시 이미지예요" 문구는 없다. 이 방의 멤버는 1명이다.
- 화면 멈춤: 마이 탭을 처음 연 무렵 약 1.7초(프레임 100개) 멈춘 기록이 로그에 있다. 얼굴 공장이 3D 엔진을 처음 만드는 순간으로 보인다(앱을 켠 뒤 한 번). 줄일 수 있는지는 8단계에서 본다.
