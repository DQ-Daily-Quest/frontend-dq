# STEP 12-A 실서버 수동 검증 절차

자동 테스트는 FakeApi/MockWebServer만 쓰고 실서버를 호출하지 않는다. 아래는 사람이 테스트 계정으로 직접 확인하는 절차다. 실제 데이터를 바꾸는 항목(★)은 테스트용 계정·방에서만 한다.

## 사전 준비
- 계측 테스트는 앱 데이터를 건드리지 않도록 `gradlew connectedDebugAndroidTest` 대신 아래 방식으로 실행한다. Gradle의 connected 작업은 끝날 때 앱과 테스트 APK를 **uninstall**해서 앱 데이터(로그인 세션 포함)가 지워진다.
  ```
  ./gradlew assembleDebug assembleDebugAndroidTest
  adb install -r -t app/build/outputs/apk/debug/app-debug.apk
  adb install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
  adb shell am instrument -w -r com.dailyquest.app.test/com.dailyquest.app.DQTestRunner
  ```
  테스트 앱은 `InMemoryTokenStore`를 써서 실제 세션 저장소를 읽거나 쓰지 않는다.
- 앱 아이콘으로 실행해 로그인 화면이 먼저 뜨는지 확인한다(3D 테스트 화면은 런처에 없다).

## 1. 인증
1. ★ 이메일 가입 → 로그인 → 앱 종료 후 재실행 시 세션 복원.
2. Google / Kakao 로그인 → 마이페이지에서 비밀번호 변경 메뉴가 숨겨지는지(hasPassword=false).
3. 비밀번호 찾기: 가입한 이메일로 코드 요청(★ 메일 발송) → 코드 확인 → 새 비밀번호 → 로그인 화면 복귀, 새 비밀번호로 로그인.
4. 로그아웃 후 다른 계정으로 로그인했을 때 이전 계정의 방·알림·배지가 보이지 않는지.
5. ★ 회원 탈퇴는 폐기용 계정으로만.

## 2. 방·미션·인증·보상
1. ★ 방 생성(공개/비공개) → 다른 계정으로 코드/목록 가입 → 방장 전용 메뉴가 멤버에게 보이지 않는지.
2. 미션 목록·상세 이동, 만료된 미션 표시.
3. ★ 사진·영상 인증 제출 → 다른 멤버 계정으로 승인/거절 → 거절 뒤 재인증.
4. 승인 후 코인이 한 번만 지급되는지(중복 승인 시도 포함), 연속 달성 표시.
5. 영상 재생: 상세 화면에서 재생, 뒤로가기·화면 회전·앱 백그라운드 후 소리가 남지 않는지.

## 3. 상점·마이페이지
1. 상품 목록, ★ 구매 → 코인 잔액·보유 상태·인벤토리 반영. 코인 부족 시 안내.
2. ★ 닉네임 수정, ★ 비밀번호 변경(이메일 계정).

## 4. 피드·알림
1. 방 피드 조회·페이지 로딩·새로고침, 사진/영상 표시.
2. ★ 리액션 등록/취소(1인 1리액션 규칙), ★ 본인 PENDING 인증 삭제.
3. 알림함 목록·읽지 않음 필터, ★ 개별/모두 읽음 → 배지가 서버 값과 일치.
4. 앱 복귀 시 배지 갱신.

## 5. FCM (백엔드 팀과 협력 필요)
자동 테스트는 실제 푸시를 보내지 않는다. 백엔드 팀이 테스트 계정으로 아래 이벤트를 발생시킨다.
1. 로그인 후 알림 권한 허용 → 서버에 토큰이 등록되었는지 백엔드 DB에서 확인(토큰은 로그에 남기지 않는다).
2. 포그라운드 / 백그라운드 / 앱 종료 상태에서 PROOF_SUBMITTED, PROOF_APPROVED, PROOF_REJECTED, NEW_APP_MISSION, NEW_MEMBER_MISSION 수신 후 알림 탭 → 해당 화면 이동.
3. 권한 거부 상태에서 앱 나머지 기능이 정상인지.
4. 로그아웃한 기기에는 푸시가 표시되지 않고, 로그아웃·계정 전환 시 알림 트레이가 비워지는지.
   서버에 FCM 토큰 삭제 API가 없어 이전 계정의 푸시가 기기로 계속 전송될 수 있다(백엔드 요청 사항).
